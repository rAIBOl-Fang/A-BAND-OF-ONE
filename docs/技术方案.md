## 1. 结论总览

| 议题 | 冻结结论 |
|---|---|
| 音色 | **混合采样包 + 实时变调**：钢琴/小提琴使用 EIAD-v1，单簧管使用 PCM16LE；不用纯实时合成，也不用 Opus |
| 采样组织 | 钢琴 7 个、同源小提琴 7 个、单簧管 9 个根音，**共 23 个源采样**；实时变调生成 63 个可弹目标音，不存 63 份完整采样 |

## 2. 硬边界与职责

- 使用 ESP-IDF **5.5.5**；自定义 16MB 分区表中 factory 为 `0x10000`、`0x300000`（3MiB），无 OTA。
- GPIO8 是 LED、麦克风、扬声器共用电源域：下游命令输出先锁低，GPIO8 拉高并等待稳定后，才初始化 WS2812 与 I2S；运行中关电须先停止全部消费者。
- 扬声器 I2S 固定接线为 BCLK GPIO14、WS GPIO13、DATA_OUT GPIO15；GPIO11、GPIO0、GPIO19/20 不复用。
- 第二课 Host Action v1（`kind 0x05` / Report ID `0x11`）只保留在课程母本源码中，最终 A Band of One 镜像不初始化其 HID/BLE/App 产品链路；本项目通信只走 ESP32-S3 内建 USB-Serial/JTAG。
- 编译前复制固件到纯 ASCII 路径；**永不执行 `erase_flash`**。
- 板端处理实时声音、状态机、计时、判定与灯效；网页处理选曲、谱面渲染、红蓝提示与结果显示。网页不调度发声时刻，也不裁决按键对错。

## 3. 音色路线：混合采样包 + 实时变调

### 3.1 为什么不是纯实时合成

纯实时合成的 Flash 占用很小，但在短工期内稳定地做出「钢琴 / 弦乐 / 单簧管」三种可识别音色，风险主要在听感而不是算力。尤其钢琴的起音与衰减难以用极少量振荡器可靠模拟。PRD 的验收是 0.5 秒内能被人耳明确区分，而不是证明合成算法；采样可把风险放在离线资产处理，板端播放保持简单、可验证。

### 3.2 为什么按乐器选择存储格式

现有 `easy-input-maker` 已有离线可用的 IMA-ADPCM 探针：48kHz 单声道 13,369 样本由约 26.7KB PCM16 压至 6,872B，约为 3.9:1；解码器是本地 C++ 实现，按帧顺序解码，适合钢琴和小提琴等已通过 EIAD 听测的资产。Opus 探针虽把同一诊断音频压到 1,734B，但引入更重的解码依赖、随机定位和循环段处理复杂度，本项目容量不要求采用 Opus。

单簧管采用不同的存储格式是针对已验证问题的最小根治：路径④保留了正确的起音、逐根循环终点和 20ms 交叉淡化，但 EIAD-v1 每 10ms 重置固定步长索引，在 F4 以上形成用户听到的电音和不稳定。单簧管 9 枚候选音改为未经有损压缩的连续 PCM16LE，仍由同一根音渲染器负责实时变调、循环和释放；这不是换源，也不是提高增益补偿。

### 3.3 资源模型与 Flash 预算

不采用「21 音 × 3 乐器 = 63 个完整采样」：这会使音频本身约 2MiB 以上，并使全量 PCM 缓存超过 8MiB PSRAM。也不再采用每件乐器仅 3 根音的网页试听基线：其最坏变调达到 ±11 半音，足以改变钢琴共振、弦乐颤音和单簧管管腔共鸣。

P1' 的候选组织是钢琴 7 个、同源小提琴 7 个、单簧管 9 个根音，共 23 个源采样。钢琴与单簧管的根音约每 3--6 个半音分布，实时变调覆盖 C3--B5 的 21 个唱名，单音目标为最多 ±3 半音。钢琴使用本地已有的 `B2 / F#3 / C4 / F#4 / C5 / F#5 / C6`；弦乐采用已经网页验收的 VSCO Solo Violin `Arco Vib f` 同源 `G3 / C4 / E4 / G4 / C5 / E5 / A5`。G3--B5 最近根音最大变调 ±2 半音，C3--F#3 是小提琴物理音域下限造成的例外。单簧管采用 `tonejs-instruments` 的 `D3 / F3 / A#3 / D4 / F4 / A#4 / D5 / F5 / A#5`：用户接受其项目级 CC BY 3.0 声明，逐文件哈希与归属在入库前核验，并永久标注“原始作者未核实”。

| 项目 | 预算 / 依据 |
|---|---|
| factory 容量 | 3,145,728B（3MiB） |
| 参考基线 app | 1,639,168B，作为保守参照，不等同于本项目最终镜像 |
| 声音包合同 | 目标为 **14 枚 EIAD + 9 枚 PCM16LE，共 1,309,174B**（钢琴/小提琴 EIAD `617,974B` + 单簧管 PCM 数据 `691,200B`）；以正式 manifest 为准 |
| 最终 app 硬门槛 | 不超过 2.4MiB，保留至少约 0.6MiB 余量 |
| 启动后 PSRAM | 运行时只分配一个固定 PCM 仓；最大单乐器实测 **1,402,514B**，小于 2MiB；板子有 8MB PSRAM |

本轮先把声音包嵌入 factory，不依赖、也不覆盖现有 `sound_a` / `sound_b` 分区。该参考工程的两个声音分区各为 `0x90000`（576KiB），是未来扩展选项；若以后需要写入，必须先备份/确认实际资产并获得用户授权，仍不得使用 `erase_flash`。

### 3.4 播放架构

1. 按安全顺序开启 GPIO8，初始化 I2S。
2. 启动后把当前乐器根音载入一个固定 PCM 仓；音频线程不解码、不动态分配。EIAD 资产由现有解码器逐根解码，PCM16LE 资产先校验 `payload_bytes == decoded_samples × 2` 后直接拷贝；两条路径最终都形成同一 `RootSample`。目标 bank 解码后钢琴 / 小提琴 / 单簧管分别占 1,402,514B / 1,008,000B / 691,200B，固定仓按最大值分配。切换乐器时先在静音帧边界进入安全态，再在同一 PCM 仓原地换入新 bank；全部压缩/原始资产留在 factory Flash，不把钢琴与小提琴同时常驻当作合法缓存方案。
3. I2S 使用 48kHz、16-bit、立体声帧（左右写相同单声道数据），128 frame 块；每块约 2.67ms。
4. 音频线程读取预先准备好的 note-on / note-off 请求，按根音与目标音高计算相位增量，插值读取 PSRAM；单音 P1' 采用短交叉淡化重触发，避免爆音。
5. 钢琴自然衰减；弦乐、单簧管使用资产清单声明的循环区与 release。S8 切换乐器、旋钮切换音区只影响下一次 note-on。
6. I2S 已输出样本数是唯一节拍时间源；谱面时长、蓝光保持、灯效与状态回报均由它派生，不能由网页计时器或普通任务延时驱动。

### 3.5 P1' 音色资产验收

- 23 枚源根音均能被完整解码；21 音 × 3 乐器共 63 个组合可单独发声；钢琴/单簧管任一目标音的根音变调不超过 ±3 半音；同源小提琴在 G3--B5 范围内不超过 ±2 半音，验收重点为区间内音色连续、音高正确且可辨识。
- 同一音高下，钢琴、弦乐、单簧管由人工盲听可在 0.5 秒内区分。
- 任一按键到发声的目标延迟小于 50ms；切换音区/乐器与重触发无明显爆音。
- 生成的 app 镜像小于 2.4MiB，PSRAM 峰值低于 2MiB；任一项不通过即先压缩/缩短资产或优化缓存，不能在未记录预算的情况下继续堆资源。

### 3.6 P1' 已确认的按键与资产执行边界

- 最终 A Band of One 固件独占 S1--S8：S1--S7 只发 note-on/off，S8 只循环乐器，旋钮只服务产品定义；不初始化第二课 USB HID、BLE HID 或 EasyInput App。原课程功能以重新烧录课程母本恢复，两套产品不在同一镜像并行。
- 暂停与待机统一为 `Standby`，主阶段不再单列 Paused。旋钮按压语义固定为 `Standby → Playing`（开始或继续）、`Playing → Standby`（暂停并立即停音）、`Finished → Standby`；一次物理点击仅由 `Pressed` 边沿驱动，`Released` 只做输入反馈。跟谱暂停保留游标、错误数与已用时间，当前未完成音符在继续后重新按完整拍长演奏。
- 旋钮旋转只在 `Playing` 阶段循环调整 C3/C4/C5 音区；`Standby`、`Finished` 不因旋转改变模式或音区。自由/跟谱模式不再由旋钮承担。
- 自由/跟谱模式只能由网页工作区通过 USB-Serial/JTAG 的 `set_mode` 请求切换；板端仅在 `Standby` 接受并以 `ack`/`error` 和后续 `state.mode` 回显为准，Playing 拒绝请求。Standby 内若切换模式，则清零旧模式本次进度；不切换模式再次按旋钮则继续。
- P1' 不新建裸 GPIO8/I2S 电源路径，复用课程母本已经验证的 `SpeakerOutput`、`AudioIoArbiter`、`PeripheralPowerController`、按键扫描、编码器和 LED 平台层；产品入口与 HID/BLE 业务层解耦。
- 23 枚源根音不采用网页试听的多层叠放补偿。离线管线统一保持 48kHz、mono、PCM16；钢琴/小提琴输出 EIAD-v1，单簧管输出连续 PCM16LE，并做逐音感知响度校准和峰值保护。钢琴按原始 SFZ 的循环/非循环分界处理，小提琴/单簧管保留起音和烘焙交叉淡化循环段。松键参数先做 A/B，不能将 40--60ms 的防 click 数值当作真实乐器 release。
- 初始交付目标为音频 payload `1,309,174B`、解码 PCM 缓存不超过 2MiB；所有转换产物必须有 manifest（来源 URL/许可/SHA-256、根音、覆盖区、处理参数、循环点、存储格式、字节数）。单簧管正式 PCM 资产只有在候选 A/B 停止门通过后才替换当前正式 EIAD。

### 3.7 网页先导验证与资产准入

在新增根音或改动固件前，先以 `console/demo-rootmap-7x3.html` 对比钢琴 3 根音和 7 根音。验收者应在 C3、A3、G4、B5 四点往返切换两套映射，并确认 7 根音版本没有明显的音色突变或异常音量；页面同时展示每个目标音的实际根音与半音位移。单簧管另以 `console/demo-clarinet-probe.html` 验证现成样本的低/中/高锚点和 9 根音映射；通过后才下载其余 6 枚小文件。下载量较大时由用户手动下载、解压和校验。

## 4. 乐谱 JSON 协议 v1

### 4.1 乐谱文档（文件 / 网页内存模型）

```json
{
  "schema": "abo.score",
  "version": 1,
  "id": "twinkle",
  "title": "小星星",
  "bpm": 90,
  "notes": [
    { "n": 0, "b": 1 },
    { "n": 0, "b": 1 },
    { "n": 4, "b": 1 },
    { "n": 4, "b": 1 }
  ]
}
```

| 字段 | 规则 |
|---|---|
| `schema` | 固定为 `abo.score` |
| `version` | 当前固定为整数 `1` |
| `id` | ASCII 标识，1—32 字符；用于日志与回执关联 |
| `title` | 曲名，UTF-8，最多 48 字节 |
| `bpm` | 60—180 的整数 BPM |
| `notes` | 1—128 项的有序数组 |
| `n` | 唱名索引：`0=do, 1=re, 2=mi, 3=fa, 4=sol, 5=la, 6=si` |
| `b` | 音符拍数，范围 `0.25—8`，必须为 0.25 的整数倍 |

`n` 与 `b` 是 `prototype.js` 中 `SCORE` 的原字段，故原型可无损升级到本协议。不要额外保存 `solfege` 字符串，避免它与 `n` 不一致；不要在 v1 的单音符中写 `o`（音区），因为当前 PRD 定义音区为演奏中的玩家控制状态，而未定义「音区错」的严格判定。

板端在接收时将 `b × 96` 转为内部 tick；若结果不是整数、字段越界、曲名/ID 超限或 note 数不匹配，则拒绝整曲。

### 4.2 USB Serial/JTAG 传输事务

老师工程的 host link 使用换行 JSON，并有 768B 接收缓冲；其 Pattern 因长复合消息可能截断而按 bank 分行。本项目沿用「换行 JSON + ACK / error」的形式，但不复用鼓机 Pattern 的 `6×16` 十六进制格式。运行时传输使用 ESP32-S3 内建 USB-Serial/JTAG，不使用 TinyUSB CDC；串口参数为 115200、8N1。115200 是浏览器打开参数，不代表应用依赖波特率产生时钟。

连接后网页必须先发送 `{"t":"ping","v":1}`。板端返回 `hello`（至少含 `product:"abo"`、`protocol:1`、固件版本）和一份 `state` 后，页面才进入“已连接”；仅成功打开 COM 口不得视为连接成功。候选端口可按 Espressif VID `0x303A` 过滤，但 PID 与 COM 号须经真机记录后再决定是否收窄，不能把 BOOT 下载模式标识误当运行时合同。浏览器应忽略非 JSON 诊断行；正式协议发送的每行必须是完整 JSON，且含换行后不超过 768B。

一首歌必须经过以下事务；每个 `score_chunk` 最多 16 个音符，以保证一行小于 768B：

```json
{"t":"score_begin","v":1,"tx":"7fa31c09","schema":"abo.score","score_version":1,"id":"demo","title":"演示曲","bpm":90,"count":4}
{"t":"score_chunk","v":1,"tx":"7fa31c09","seq":0,"notes":[{"n":0,"b":1},{"n":0,"b":1}]}
{"t":"score_commit","v":1,"tx":"7fa31c09","chunks":1,"crc32":"0123abcd"}
```

所有串口消息的 `v` 固定表示**传输协议版本**，当前为 `1`；文件中的 `version` 在 `score_begin` 中改名传输为 `score_version`，并与 `schema:"abo.score"` 一起由板端复验。两种版本不得共用一个字段。

| 消息 | 方向 | 行为 |
|---|---|---|
| `score_begin` | 网页 → 板端 | 建立 `tx` 标识的暂存会话并校验 `schema`、`score_version` 与元数据；不触碰当前有效曲目 |
| `score_chunk` | 网页 → 板端 | 在相同 `tx` 下依序写入暂存区；事务、序号或字段非法即失败 |
| `score_commit` | 网页 → 板端 | 校验分片数、总音符数和 CRC32；全部通过才原子替换当前曲目 |
| `set_mode` | 网页 → 板端 | 请求 `score`/`free`；仅 Standby 可接受，切换模式时清零旧模式本次进度，成功后以 `ack` 与 `state.mode` 确认 |
| `set_volume` | 网页 → 板端 | 请求 0—100 的 RAM 音量目标；由音频消费者在块边界平滑应用，成功后以 `ack` 与 `state.volume` 确认 |
| `transport` | 网页 → 板端 | P3 仅接受 Finished 阶段的 `action:"reset"`；网页不远程开始、暂停或继续 |
| `ack` | 板端 → 网页 | 返回已确认的命令、曲目 ID 与当前版本 |
| `error` | 板端 → 网页 | 返回命令与机器可读原因；旧曲保持有效 |
| `state` | 板端 → 网页 | 模式、阶段、乐器、音区、游标、错误数、运行状态 |
| `input` | 板端 → 网页 | S1—S9 的不可合并实体 `pressed`/`released` 瞬态；用于旋钮反馈和曲终确认，不替代 `state.keys` |
| `judge` | 板端 → 网页 | 一次按键的对/错、目标索引、累计错误数；网页据此切换红/蓝 |
| `result` | 板端 → 网页 | 曲终的错误数与耗时毫秒；网页仅格式化显示 |

**原子性规则**：上传未完成、断线、CRC 错误或任一字段错误，板端不得进入半首新曲，不得清除上一首有效曲。网页收到 `ack(score_commit)` 前也不得把新曲显示为已装载。

**事务与回执规则**：`tx` 为网页为每次上传生成的 8 位小写十六进制标识；`score_begin/chunk/commit` 与对应 `ack/error` 都必须携带同一 `tx`。同一时刻板端只保留一个暂存事务；新 `score_begin` 可废弃未提交暂存，但不能清除当前有效曲。网页逐步等待匹配 `tx` 与命令名的回执，单步 2 秒超时即中止并保留旧曲。

**CRC32 规范字节流**：采用 CRC-32/ISO-HDLC（多项式 `0x04C11DB7` 的 reflected 实现 `0xEDB88320`，初值与终值异或均为 `0xFFFFFFFF`）。依次输入 ASCII `abo.score` 后的 `00`、`score_version:uint8`、`id_len:uint8 + id ASCII`、`title_len:uint8 + title UTF-8`、`bpm:uint16 LE`、`count:uint16 LE`，随后每个音符输入 `n:uint8 + ticks:uint16 LE`，其中 `ticks=b×96`。传输协议字段 `v` 和事务字段 `tx` 不进入乐谱内容 CRC。网页和板端都只对这组规范字节计算，十六进制结果固定为 8 位小写；禁止直接对 `JSON.stringify()` 文本或 UTF-16 字符单元计算。

### 4.3 P3 状态进度与实体输入事件

板端持续状态可携带以下字段；新网页必须校验字段类型和范围，缺失时只能降级为逐音跳转，不能自行计拍：

```json
{
  "t": "state", "v": 1, "mode": "score", "phase": "playing",
  "subphase": "holding", "score_id": "twinkle", "score_crc32": "89abcdef",
  "cursor": 12, "note_ticks": 32, "note_total_ticks": 96, "volume": 70
}
```

- `score_crc32` 必须是板端当前活动谱的 canonical CRC32；网页只有在 `score_id + score_crc32` 与本地谱一致时才渲染该谱，禁止仅凭 ID 套用内置《小星星》。
- `note_ticks` 是当前音已完成的 tick，`note_total_ticks` 是当前音总 tick，必须满足 `0 <= note_ticks <= note_total_ticks`；Waiting、Standby、Finished 或无活动音时两者均为 0。
- `cursor == note_count` 只允许出现在 Finished；网页不知道本地音符总数时不得猜测曲终。

实体输入作为不可合并的关键事件回传：

```json
{"t":"input","v":1,"seq":104,"control":"s9","phase":"pressed"}
{"t":"input","v":1,"seq":105,"control":"s9","phase":"released"}
```

`control` 为 `s1`—`s9`，`phase` 为 `pressed|released`，`seq` 为可自然回绕的单调 `uint32`。事件进入关键 FIFO，不能使用 latest-state 槽合并；网页用它实现 S9 两个工作区的短暂“按压”反馈。S1—S8 的持续颜色仍以 `state.keys` 为准。

网页与板端控制合同如下：`set_mode(mode=score|free)` 仅 Standby 接受；`set_volume(value=0..100)` 在 Standby/Playing 接受，只更新 RAM 目标并按音频块边界平滑；`transport(action=reset)` 仅 Finished 接受，用于完成卡片回 Standby。所有请求等待匹配 `ack` 后，再等待包含目标值的 `state`；网页不得发送 `start|pause|resume`，实体旋钮是开始/暂停/继续的唯一入口。Finished 阶段任意实体 S1—S9 的 Pressed 先被板端消费并回 Standby，不发声、不切乐器、不重新开始。

### 4.4 严格模式时间语义

- 按下正确的 `n`：板端发声并发送 `judge(ok)`；网页依据后续 `state.keys`、`cursor`、`note_ticks` 和 `note_total_ticks` 把当前键从红变蓝并显示进度，游标推进完全由板端状态决定，网页不得按 `b × 60 / bpm` 自行推进。
- 按错：计入错误、短促错误提示、游标不推进，红光保持；等待时间计入总用时。
- 主动暂停即进入 Standby：音频停、谱面停、主动暂停区间不计时；未切换模式时再次按旋钮从原游标恢复，当前未完成音符需重新完整演奏；若网页切换模式则清零旧进度。
- 自由模式：不读取谱面、不产生 `judge` 或 `result`，按住发声、松开止音。

## 6. P0'—P3' 实施与真机验收

### P0' 安全上电复验

**实现范围**：历史 P0' 已在课程母本内证明 GPIO8 安全时序、WS2812 与 I2S 启动声可用。独立固件基线继续复用这些已验证平台层，不重写裸驱动；启动音采用已验收钢琴 C4。

**真机验收**：正常开机出现 USB-Serial/JTAG 端口，网页完成 `ping → hello/state`；冷启动灯链可见、扬声器播放钢琴 C4，按键与旋钮扫描正常；系统不再枚举为 EasyInput HID、不广播 EasyInput BLE、不连接 EasyInput App；停止共享消费者后断电无反灌。记录运行时 VID/PID/COM，仅烧录 app 所需分区且不执行 `erase_flash`。

### P1' 声音引擎

**实现范围**：48kHz I2S 连续渲染、I2S 采样时间轴、23 枚源根音混合存储（14 枚 EIAD-v1 + 9 枚 PCM16LE）、单一固定 PCM 仓的静音帧边界换仓、变调、S1—S7 与音区映射、S8 乐器循环。

**真机验收**：63 个「21 音 × 3 乐器」组合均可发声；旋钮切换音区仅影响后续按键；S8 循环正确；三音色在 0.5 秒内可区分；按键到声音小于 50ms；镜像和 PSRAM 预算均通过。

### P2' 双模式状态机

**实现范围**：板端严格跟谱判定、等待按对、暂停即 Standby、自由演奏、完成琶音、D1—D5 节奏/庆祝光效；旋钮按压只做开始/暂停/继续，旋钮旋转只在演奏中调音区；模式由网页 `set_mode` 请求切换且仅 Standby 接受。使用内置《小星星》或串口测试夹具完成板端 HIL，不要求最终网页。

**真机验收**：连续三次弹错均不推进且错误数正确；按对后蓝光保持对应拍长再进入下一音；等待时间计入用时，Standby 暂停时间不计；自由模式无判定；Playing 按旋钮进入 Standby 后网页可切换 `score/free` 并收到板端确认，未切模式再次按旋钮可继续；旋钮仅在 Playing 调音区；S8/D1—D5 符合 PRD §04。该阶段对应 PRD §09 的板端功能链路，页面视觉验收留给 P3'。

### P3' 网页控制台

**实现范围**：单文件 HTML；Web Serial 打开、应用层握手与断线清理；完整 UTF-8 `.abo.score.json`（`abo.score v1`）选择/拖放、校验、预览、带 `tx` 的分片上传、规范 CRC32、逐步 ACK/超时/回滚；网页工作区在 Standby 发送 `set_mode`，音量在 Standby/Playing 通过 `set_volume` 请求并等待板端确认，曲终仅用 `transport reset` 返回 Standby；键盘红蓝提示、实体旋钮 `input` 反馈、按拍游标、中央固定指针与活动谱带平滑移动、板端状态映射和成绩显示。

P3 不在网页内调用 AI，也不支持 MIDI、MusicXML、PDF 或图片识谱。导入控件下方须放置静态帮助卡，使用以下文案指导用户借助外部识图 AI 制作文件：

> **如何用 AI 生成乐谱文件**  
> 将清晰、正向的单声部五线谱图片上传给支持识图的 AI，并发送：  
> “请将五线谱转换为 `abo.score v1` JSON。输出 `schema、version、id、title、bpm、notes`；音符使用 `{n,b}`，其中 do–si 对应 0–6，`b` 为拍数。遇到和弦、升降音、休止符或无法辨认的内容，请列出并让我确认，不要猜测。只输出 JSON。”  
> 将结果保存为 UTF-8 编码的 `曲名.abo.score.json` 后导入。AI 可能识别错误，请先核对音符、节拍和 BPM。

长谱采用活动谱带：谱面区中央设置一个固定指针，五线谱或简谱的当前活动轨道按实际音符中心以 `translate3d` 平滑移动，音符宽度按 `b` 成比例；隐藏轨道不参与位置计算。游标位置及当前拍内比例来自板端累计拍数、`note_ticks` 与 `note_total_ticks`，Waiting/Standby/断线冻结，网页只在相邻真实状态快照之间做 CSS 过渡，不建立独立计拍器。收到权威 `standby + cursor=0`、成功装载、切换记谱法或窗口尺寸变化时即时复位/重算。内置《小星星》使用完整 42 音，任意合法导入谱使用同一渲染器。

**真机验收**：Chrome/Edge 中导入/选曲、握手、下发成功后网页按板端状态显示红光提示；坏 CRC、乱序分片、超时均返回明确错误且旧曲仍可开始；实体按键带来板端出声与正确蓝光持续，S9 按压在两个工作区同步反馈；板端 `result` 与网页显示的错误数/用时一致；完成卡片支持实体任意键或电脑/鼠标请求回 Standby；从选曲到首次听见声音不超过 15 秒；拔线后两个连接按钮、待确认事务和设备状态均清空，无幽灵状态。
