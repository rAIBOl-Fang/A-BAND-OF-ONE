# Web 控制台功能与通信框架（v1）

> 状态：2026-09-05 页面框架已落到 `console/index.html`；视觉可继续由 UI agent 迭代。本文同时冻结 P3 控制责任、实时反馈字段与 `.abo.score.json` 导入边界；具体实现按 P3 任务门推进。

## 1. 已确认的功能骨架

控制台仍是 PRD 约定的单文件 HTML，通过 Chrome/Edge 的 Web Serial 与独立 A Band of One 固件的 ESP32-S3 内建 USB-Serial/JTAG 双向通信，不依赖 TinyUSB HID、BLE 或 EasyInput App。顶层有三个同级工作区：**跟谱练习 / 自由演奏 / 乐谱库与导入**；其中只有前两者是板端的演奏模式，乐谱库与导入不是第三种模式。页面必须具备下列六类信息/交互：

1. **双演奏模式**：跟谱弹奏与自由演奏可鼠标切换。跟谱视图呈现严格判定；自由视图不判错、按键即发声。模式在演奏中锁定，保持原型的“待机可切换、演奏中旋钮调音区”语义。
2. **键盘还原区**：完整呈现 S1--S8、旋钮、D1--D5。S1--S7 显示唱名、当前实际音高和功能；S8 显示当前/下一乐器。跟谱时遵循 PRD 红色待按 → 蓝色持续拍长；错误不推进。旋钮必须可显示左转、右转、按下的当前提示。
3. **乐谱库与导入**：只支持本机 UTF-8 `.abo.score.json`（`abo.score` v1）。导入页校验文件、展示曲名/BPM/音符数或错误原因；通过后加入本次浏览器会话的曲库，不自动下发到键盘，不提供网页内编辑、MIDI/MusicXML/PDF/图片识谱或文件系统写入。导入控件下方提供外部 AI 转换提示词，但网页不调用 AI 服务。
4. **跟谱曲目选择**：跟谱练习页显示内置与已导入曲目；用户选择后显式点击“装载到键盘”，复用带 `tx` 的 `score_begin` / `score_chunk` / `score_commit`。仅收到匹配事务的 `ack(score_commit)` 后才显示该曲已装载并可开始。
5. **谱面区**：位于键盘还原区上方；跟谱时展示已装载曲目的曲名、BPM、音符块和当前位置/节拍引导；自由模式保留同一区域但可改为最近演奏轨迹，不做严格评分。
6. **状态与音量区**：显示连接状态、模式、当前乐器、音区、BPM、运行阶段；跟谱曲终还应显示错误次数和用时。网页可调音量；真实接入后由板端确认实际值再回显，不能把浏览器滑块值当作设备真相。

## 2. 责任与状态真相

| 状态 | 唯一真相 | 网页职责 |
|---|---|---|
| 按键、判定、拍长、曲目游标、错误数、用时 | 板端 P2 状态机 / I2S 时间轴 | 根据回传渲染，不自行判定或推进 |
| 键盘实际发声、音区、乐器、LED 光效 | 板端 | 发送请求后等待确认状态回显 |
| 页面布局、主题、鼠标悬停、提示文案 | 网页 | 本地管理 |
| 乐谱导入、校验与会话曲库 | 网页 | 只接受 `abo.score` v1；导入不自动下发 |
| 已装载曲目与上传进度 | 板端 `score_commit` 确认 | 未收到确认不得显示“已装载” |

这条边界保证：浏览器卡顿、USB 短时延迟或断开，最多影响画面，不会让音频时间轴、严格判定或键盘声音失控。

## 3. 双向反馈如何工作

```text
实体键 / 旋钮
      ↓
板端状态机、I2S 时间轴（唯一真相，立即发声/判定）
      ↓ USB 串口：state / input / judge / result
浏览器串口读取器 → 页面状态仓 → 键色、谱面、状态面板

网页鼠标：Standby 模式 / 音量（Standby 或 Playing）/ 选曲 / 装载已导入乐谱；曲终 reset
      ↓ 发送已冻结的请求（等待 ACK 与 state）
板端校验并实际执行
      ↓ USB 串口确认 state / ack
浏览器仅在确认后更新为设备实际状态
```

连接链路必须按以下顺序建立：

1. `navigator.serial.requestPort()` 仅以 Espressif VID `0x303A` 缩小候选范围，不依赖固定 COM 号或未经真机确认的 PID。
2. 以 115200、8N1 打开端口，创建单一、可取消的流式 UTF-8 解码器和按行缓冲。
3. 网页发送 `{"t":"ping","v":1}`；只有收到 `hello(product="abo", protocol=1)` 和首份 `state` 才把两个连接按钮同时置为“已连接”。
4. 握手超时、读写异常、用户断开或 USB 拔出时，取消 reader、关闭 writer、调用 `releaseLock()`、清空行缓冲/待确认事务/设备状态，页面回到未连接。

已冻结的乐谱事务、CRC、控制请求与状态回传见 `docs/技术方案.md`：

- 网页 → 键盘：`ping`、带 `tx` 的 `score_begin`、`score_chunk`、`score_commit`、Standby 下的 `set_mode`、Standby/Playing 下的 `set_volume`、Finished 下的 `transport(action="reset")`。
- 键盘 → 网页：`hello`、`ack`、`error`、`state`、不可合并的 `input`、`judge`、`result`。

所有串口消息的 `v` 是传输协议版本；`score_begin` 另带 `schema:"abo.score"` 与 `score_version:1`。不得把乐谱文件 `version` 直接混作传输 `v`。

控制请求合同已冻结：`set_mode.mode` 只能为 `score|free` 且仅 Standby 接受；`set_volume.value` 为整数 `0..100`，在 Standby 或 Playing 只改 RAM 目标并等待板端平滑确认；网页不发送 `start|pause|resume`，实体旋钮是开始/暂停/继续的唯一入口；`transport.action="reset"` 只在 Finished 使用。所有请求等待匹配 ACK 与随后 state，不得乐观改写设备状态。`KEY_DOWN/KEY_UP`、`ENCODER_*` 不进入网页到板端的演奏输入协议，屏幕键盘和网页旋钮是状态显示器。

### 3.1 实时反馈字段与状态边界

`state` 是持续状态唯一真相，可选增量字段包括 `score_crc32`、`note_ticks`、`note_total_ticks`。网页必须校验类型和范围：`0 <= note_ticks <= note_total_ticks`；Waiting、Standby、Finished 或无活动音时两者为 0。只有 `score_id + score_crc32` 与本地导入曲一致时，网页才渲染对应谱面，不能仅凭曲名或 ID 套用《小星星》。

实体 S1--S9 另以不可合并的 `input` 事件反馈：

```json
{"t":"input","v":1,"seq":104,"control":"s9","phase":"pressed"}
{"t":"input","v":1,"seq":105,"control":"s9","phase":"released"}
```

`seq` 为板端单调 `uint32`（允许自然回绕），`control` 为 `s1..s9`，`phase` 为 `pressed|released`。S1--S8 的持续键色继续来自 `state.keys`；`input` 只用于旋钮按压瞬态和 Finished 确认。Finished 阶段实体任意键被板端消费后回 Standby，不发声、不切乐器、不重新开始；网页完成卡片以 `state.phase="standby"` 为关闭条件。

### 3.2 `.abo.score.json` 完整支持与外部 AI 提示

P3 的“完整支持”包括：文件选择/拖放、`abo.score v1` 结构与范围校验、错误定位、会话曲库预览、显式装载、`score_begin/chunk/commit` 原子事务、canonical CRC32、ACK/state 确认、红蓝按键指导、拍长游标、长谱横向连续滚动、拔线清理与按 `score_id + score_crc32` 重连恢复。当前格式只收 1—128 个单声部自然唱名音符，`n=0..6`，`b=0.25..8` 且为 0.25 倍数，BPM 为 60—180；不增加休止、升降号、和弦或逐音八度。

导入控件下方放置静态说明卡，文案固定为：

导入区的页面顺序固定为：先显示“会话曲库”，再显示“如何用 AI 生成乐谱文件”，用户进入导入工作区即可先看到可装载的曲目。

> **如何用 AI 生成乐谱文件**  
> 将清晰、正向的单声部五线谱图片上传给支持识图的 AI，并发送：  
> “只识别主旋律；若为钢琴大谱表，只取高音谱表，忽略低音伴奏、和弦及伴奏升降号。输出字段仅包括 `schema、version、id、title、bpm、notes`：`schema` 固定为 `"abo.score"`，`version` 为 1，`id` 使用 ASCII，`bpm` 为 60–180 的整数；音符使用 `{n,b}`，do–si 对应 `n=0–6`，`b` 为拍数，四分音符为 1，且必须是 0.25 的倍数。未标注 BPM 时使用 90。系统不支持休止符：删除休止的空拍，让后续音符立即衔接。遇到无法辨认、和弦、主旋律升降音或节拍不确定时，不要猜测，先列出待确认项。确认无歧义后，只输出 JSON，不要 Markdown、解释或额外字段。保存为 UTF-8 的「曲名.abo.score.json」。”  
> 将结果保存为 UTF-8 编码的 `曲名.abo.score.json` 后导入，并先人工核对音符、节拍和 BPM。

说明卡不得提供自动转换按钮、API Key、第三方上传或“识别结果必然正确”的提示；它只指导用户在项目外使用 AI。

### 3.3 谱面游标与长谱

内置《小星星》为完整 42 音；导入谱与内置谱使用同一渲染器。谱面区保留一个位于中央的固定指针，当前活动记谱轨道按实际音符中心以 `translate3d` 平滑移动，音符宽度仍按 `b` 成比例。五线谱与简谱各自独立计算几何位置，隐藏视图不参与坐标；游标与连续拍内位置来自板端累计拍数、`note_ticks` 和 `note_total_ticks`。Waiting、Standby、断线和错误时冻结，网页仅在相邻真实快照间做 CSS 过渡，不使用浏览器计时器推进真实游标。收到权威 `standby + cursor=0`、成功装载新谱、记谱法切换或窗口尺寸变化时即时重算，使第二轮从第一音位置开始。

## 4. 实时性与可行性

可行，但分工必须正确：

- **声音与严格节奏不是由网页实时控制**。按键到发声、按错是否推进、蓝色维持多久，都在板端完成；因此网页不参与音频关键路径。
- **网页是低频、事件驱动的可视化指挥台**。每次按键、判定、状态改变和曲终回传即可让界面同步；必要时可补充低频状态心跳。USB 串口与浏览器渲染不具备硬实时保证，不能承担采样级节拍或声音播放。
- **网页控制要走“请求—确认—回显”**。例如用户拖动音量条，页面先显示“正在同步”，收到板端 `state`/`ack` 后才显示真实音量；模式切换同理。断线后停止发请求、标记未连接，不保留幽灵状态。

对本项目的 8 键、旋钮、每拍一次引导和状态展示而言，这种事件量远低于 USB 串口和浏览器的处理能力，满足“实时反馈”的体验目标；它不等价于用网页做实时音频引擎。
